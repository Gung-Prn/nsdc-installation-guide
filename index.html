Quick Start — ติดตั้งตั้งแต่ศูนย์จนเปิดเว็บได้

ส่วนนี้เป็นลำดับย่อสำหรับผู้เข้าอบรมที่ยังไม่มี Node.js หากต้องการรายละเอียดหรือพบข้อผิดพลาด ให้ดูหัวข้อถัดไปในคู่มือ

Windows 10/11

  1. ดาวน์โหลด Node.js 24 LTS แบบ Windows Installer (.msi) จาก nodejs.org
  2. ติดตั้งตามขั้นตอน โดยคงตัวเลือกเพิ่ม Node.js ลง PATH แล้วเปิด PowerShell ใหม่
  3. ตรวจเวอร์ชัน:
node --version
npm --version
  1. แตกโฟลเดอร์เว็บ เช่น C:\NSDC\nsdc-frontend-dev
  2. เปิด PowerShell แล้วเข้าโปรเจกต์:
Set-Location "C:\NSDC\nsdc-frontend-dev"
  1. เปิด .env.web และใส่ API key/tag:
notepad .env.web
  1. ติดตั้ง dependency, build และ start:
npm.cmd install
npm.cmd run build
npm.cmd start
  1. เปิด http://localhost:3000/mission/catalog

macOS

  1. ดาวน์โหลด Node.js 24 LTS แบบ macOS Installer (.pkg) จาก nodejs.org
  2. ติดตั้งตามขั้นตอน แล้วเปิด Terminal ใหม่
  3. ตรวจเวอร์ชัน:
node --version
npm --version
  1. เข้าโฟลเดอร์โปรเจกต์:
cd "/path/to/nsdc-frontend-dev"
  1. ตรวจและแก้ .env.web ใน root ของโปรเจกต์
  2. ติดตั้ง dependency, build และ start:
npm install
npm run build
npm start
  1. เปิด http://localhost:3000/mission/catalog
เมื่อ Terminal แสดง Ready และหน้า Catalog เปิดได้ ให้เลือก Landsat 9 แล้วกด See result เพื่อยืนยันว่าการติดตั้งและการเชื่อมต่อ API สำเร็จ
หยุดเว็บด้วย Ctrl + C บน Windows หรือ Control + C บน macOS

1. ภาพรวมและคำตอบเรื่อง Windows

ไม่ต้องแก้โค้ดเพิ่มสำหรับ Windows npm launcher ของโปรเจกต์ใช้ Node.js API ที่ทำงานได้ทั้ง Windows และ macOS ความแตกต่างอยู่ที่รูปแบบ path, โปรแกรม Terminal และคำสั่งหยุด process เท่านั้น

เมื่อติดตั้งสำเร็จ เว็บจะทำงานที่:

http://localhost:3000/mission/catalog

พฤติกรรม Catalog ปัจจุบัน:

  • อ่านรายการจาก NSDC Catalogue API
  • แสดงเฉพาะรายการที่ enabled: false
  • แสดงเฉพาะรายการที่ tags มีค่าตรงกับ api_get_catalog_tag ใน .env.web
  • ค้นหาภาพด้วย POST และคง payload ตามระบบ Catalog เดิม

2. สิ่งที่ต้องเตรียม

รายการ ข้อกำหนด วิธีตรวจ
ระบบปฏิบัติการ Windows, Windows + WSL หรือ macOS ไม่ต้องเปลี่ยน source code ระหว่างระบบ
Node.js แนะนำ Node.js 24 LTS; ขั้นต่ำตาม Next.js คือ Node.js 20.9.0 node --version
npm ติดตั้งมาพร้อม Node.js npm --version
Browser Chrome, Edge, Firefox หรือ Safari รุ่นปัจจุบัน ต้องเปิด WebGL และ JavaScript
Network ออก HTTPS ไปยัง NSDC API และบริการ basemap ได้ ดู allowlist ในหัวข้อ 8

อ้างอิง: Next.js system requirements ระบุ Node.js ขั้นต่ำ 20.9 และรองรับ Windows/macOS/Linux ส่วน Node.js release schedule แนะนำให้ production ใช้รุ่น LTS ปัจจุบัน

3. ชุดไฟล์สำหรับใช้งาน

ส่งทั้งโฟลเดอร์ nsdc-frontend-dev โดยต้องมีอย่างน้อย:

  • src/, public/, scripts/
  • package.json และ package-lock.json
  • next.config.ts และไฟล์ config อื่นใน root
  • .env.web ที่กำหนดค่าของลูกค้าแล้ว

ไม่จำเป็นต้องส่ง:

  • node_modules/ — ให้ติดตั้งใหม่ด้วย npm install
  • .next/ — ให้สร้างใหม่ด้วย npm run build
ห้ามเผยแพร่ .env.web ต่อสาธารณะ เพราะมี API key ควรออก key แยกสำหรับลูกค้าแต่ละราย และส่งผ่านช่องทางที่องค์กรอนุมัติเท่านั้น

4. ตั้งค่า .env.web

ไฟล์ต้องอยู่ที่ root ของโปรเจกต์ ระดับเดียวกับ package.json: 

nsdc-frontend-dev/
├─ .env.web
├─ package.json
├─ package-lock.json
├─ scripts/
├─ src/
└─ public/

รูปแบบค่าที่แนะนำ:

api_get_catalog_url=https://nsdc.gistda.or.th/core/api/catalogue/1.0/catalogues?api_key=YOUR_API_KEY
api_get_catalog_search=https://nsdc.gistda.or.th/core/api/catalogue/1.0/catalogues/{catalog_id}/stac/search
api_get_catalog_resource=https://nsdc.gistda.or.th/core/api/catalogue/1.0/catalogues/{catalog_id}/stac/queryables
api_get_catalog_tag=peeranat
  • แทน YOUR_API_KEY ด้วย key ที่ได้รับ
  • api_get_catalog_tag เป็น exact match และแยกตัวพิมพ์ใหญ่/เล็ก
  • ไม่ใส่เครื่องหมายคำพูดหรือ semicolon ท้ายค่า
  • เมื่อเปลี่ยนค่า env ให้หยุด server แล้ว start ใหม่; ไม่ต้อง build ใหม่ หากไม่ได้แก้ source code

5. ติดตั้งบน Windows

ขั้นที่ 1 — ติดตั้ง Node.js

ดาวน์โหลด Node.js 24 LTS จาก nodejs.org และใช้ Windows Installer (x64) ตามสถาปัตยกรรมเครื่อง ระหว่างติดตั้งให้คงตัวเลือกเพิ่ม Node.js ลง PATH

ขั้นที่ 2 — เปิด PowerShell ใหม่และตรวจเวอร์ชัน 
node --version
npm --version

ควรเห็น Node.js v24.x.x หรือรุ่นที่ใหม่กว่าและรองรับ

ขั้นที่ 3 — แตกไฟล์และเข้าโฟลเดอร์โปรเจกต์

ตัวอย่างเก็บไว้ที่ C:\NSDC\nsdc-frontend-dev:

Set-Location "C:\NSDC\nsdc-frontend-dev"
ขั้นที่ 4 — ตรวจและแก้ .env.web 
notepad .env.web

บันทึกเป็น UTF-8 และตรวจว่าไฟล์ไม่ได้กลายเป็น .env.web.txt

ขั้นที่ 5 — ติดตั้ง dependency 
npm install

หาก PowerShell แจ้งว่า npm.ps1 ถูกปิดกั้น ให้ใช้คำสั่งต่อไปนี้โดยไม่ต้องเปลี่ยน Execution Policy ของเครื่อง: 

npm.cmd install
ขั้นที่ 6 — สร้าง production build 
npm run build

หรือใช้ npm.cmd run build หาก PowerShell บล็อก npm.ps1

ขั้นที่ 7 — เปิดเว็บ 
npm start

เปิด Browser ไปที่:

http://localhost:3000/mission/catalog
หาก Windows Defender Firewall ถามสิทธิ์ ให้เลือกเฉพาะ Private networks เมื่อจำเป็นต้องให้เครื่องอื่นในวง LAN เข้าเว็บ หากใช้งานเฉพาะเครื่องเดียว ไม่จำเป็นต้องเปิด Public networks

ขั้นที่ 1 — ติดตั้ง Node.js

ติดตั้ง Node.js 24 LTS จาก nodejs.org หรือ Node version manager ที่องค์กรใช้อยู่

ขั้นที่ 2 — ตรวจเวอร์ชัน 
node --version
npm --version
ขั้นที่ 3 — เข้าโฟลเดอร์โปรเจกต์ 
cd "/path/to/nsdc-frontend-dev"

ต้องใส่เครื่องหมายคำพูดเมื่อ path มีช่องว่าง

ขั้นที่ 4 — ติดตั้ง สร้าง และเปิดเว็บ 
npm install

เปิด http://localhost:3000/mission/catalog

7. Start, Stop, Restart และเปลี่ยน Port

Windows PowerShell

Start

npm start

Stop: กด Ctrl + C

ตรวจ process ที่ใช้ port 3000

netstat -ano | findstr :3000

หยุดตาม PID

taskkill /PID <PID> /F

macOS Terminal

Start

npm start

Stop: กด Control + C

ตรวจ process ที่ใช้ port 3000

lsof -i :3000

หยุดตาม PID

kill <PID>

เปลี่ยนเป็น Port อื่น

npm start -- -p 3100

จากนั้นเปิด http://localhost:3100/mission/catalog

เมื่อใดต้อง build ใหม่

สิ่งที่เปลี่ยน คำสั่งที่ต้องทำ
แก้เฉพาะ .env.web Stop แล้ว npm start ใหม่
แก้ source code หรืออัปเดต dependency npm install (ถ้าจำเป็น), npm run build, npm start
เปลี่ยน port ชั่วคราว npm start -- -p PORT; ไม่ต้อง build ใหม่

8. เปิดใช้ในเครือข่ายองค์กร

หากต้องการให้ผู้เข้าอบรมเครื่องอื่นเปิดเว็บ ให้รันเว็บบนเครื่องผู้สอน แล้วใช้ IP ของเครื่องนั้นแทน localhost: 

http://<SERVER-IP>:3000/mission/catalog

หา IP ของเครื่อง

Windows

ipconfig

ดูค่า IPv4 Address ของ network adapter ที่ใช้งาน

macOS Wi-Fi

ipconfig getifaddr en0

หากใช้ adapter อื่น ให้ตรวจจาก Network Settings

Domain ที่ควรอนุญาตให้ออก HTTPS

  • nsdc.gistda.or.th — Catalogue/STAC API
  • carto.elemnt.earth — Topology style
  • s3-public.elemnt.earth — PMTiles ของ Topology
  • tiles.maps.eox.at — Satellite basemap
  • asset/thumbnail domains ที่ STAC response อ้างถึง
เปิด port ให้เฉพาะเครือข่ายที่เชื่อถือได้ เว็บมี server-side API proxy และอ่าน API key จาก .env.web แม้ key ไม่ถูกส่งตรงไป browser แต่เครื่องที่รันเว็บยังควรได้รับการควบคุมตามนโยบายองค์กร

9. ทดสอบหลังติดตั้ง

  1. เปิด http://localhost:3000/mission/catalog
  2. ตรวจว่าแผนที่ Topology แสดงผล ไม่เป็นพื้นเทา
  3. ตรวจรายการดาวเทียม
  4. เลือก Landsat 9 และตรวจว่ามี Cloud Cover, Path และ Row
  5. กด See result และตรวจว่ามีรายการภาพตอบกลับ
  6. สลับ Topology / Satellite basemap และตรวจว่าทั้งสองแบบแสดงผล
  7. พับ sidebar และตรวจว่าโลโก้ GISTDA ยังแสดงครบ
จำนวนผลค้นหาจะเปลี่ยนตามช่วงวันที่และข้อมูลใน Catalogue API เกณฑ์ผ่านคือ request สำเร็จและแสดงรายการ ไม่ควรยึดจำนวนคงที่

10. การแก้ปัญหาเบื้องต้น

อาการ สาเหตุที่พบบ่อย แนวทางแก้
node หรือ npm ไม่รู้จัก Node.js ยังไม่ติดตั้ง หรือ Terminal ยังไม่รับ PATH ใหม่ ติดตั้ง Node.js แล้วปิด/เปิด Terminal ใหม่
npm.ps1 cannot be loaded PowerShell Execution Policy ใช้ npm.cmd แทน npm
Missing ... in .env.web ไฟล์อยู่ผิดที่ ชื่อกลายเป็น .txt หรือขาด key วางไฟล์ข้าง package.json และตรวจ key ทั้ง 4 ตัว
หน้า Catalog ไม่มีรายการ tag ไม่ตรง, รายการไม่ได้เป็น enabled: false, API key ผิด หรือ cache เดิม ตรวจค่า api_get_catalog_tag แล้ว restart server
ค้นหาแล้วได้ 502 เข้า NSDC API ไม่ได้ หรือ endpoint/env ไม่ถูกต้อง ตรวจ network, API key, URL และ corporate proxy/firewall
แผนที่เป็นสีเทา PMTiles/style ถูก firewall บล็อก หรือ WebGL ปิดอยู่ เปิด domain ตาม allowlist และทดสอบ Browser รุ่นปัจจุบัน
Port 3000 ถูกใช้งาน มี server เดิมทำงานอยู่ หยุด process เดิม หรือใช้ npm start -- -p 3100
เห็น Sentry deprecation warning ตอน build คำเตือนจาก config เดิม ไม่ทำให้ build ล้มเหลว ให้ดูบรรทัดสุดท้ายว่า build สำเร็จหรือไม่

12. ล้าง Build และติดตั้งใหม่ทั้งหมด

ใช้ขั้นตอนนี้เมื่อต้องการจำลองการติดตั้งบนเครื่องใหม่ หรือแก้ปัญหา dependency/build เดิม โดยลบเฉพาะ node_modules และ .next

ก่อนเริ่ม ให้หยุด server ด้วย Ctrl + C บน Windows หรือ Control + C บน macOS

Windows PowerShell

Set-Location "C:\NSDC\nsdc-frontend-dev"

@("node_modules", ".next") | ForEach-Object {
    if (Test-Path $_) {
        Remove-Item -Recurse -Force $_
    }
}

npm.cmd cache verify
npm.cmd ci
npm.cmd run build
npm.cmd start

macOS Terminal

cd "/path/to/nsdc-frontend-dev"

rm -rf node_modules .next

npm cache verify
npm ci
npm run build
npm start

ไฟล์ที่ต้องเก็บไว้

  • .env.web — เก็บ API endpoint, API key และ tag
  • package.json — รายการ dependency และ npm scripts
  • package-lock.json — ล็อกเวอร์ชัน dependency เพื่อให้ทุกเครื่องติดตั้งได้เหมือนกัน
  • src/, public/ และไฟล์ source/config อื่น
ไม่แนะนำให้ลบ package-lock.json สำหรับการ Training เพราะ npm ci ใช้ไฟล์นี้ติดตั้ง dependency เวอร์ชันเดียวกันทุกเครื่อง หากลบแล้วใช้ npm install แต่ละเครื่องอาจได้ dependency คนละเวอร์ชัน

เมื่อติดตั้งเสร็จ เปิด http://localhost:3000/mission/catalog และทำขั้นตอนทดสอบหลังติดตั้งอีกครั้ง
