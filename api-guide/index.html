Vallaris Maps / API Training Guide

คู่มือ Vallaris STAC & Catalogue API

คู่มือใช้งาน API สำหรับค้นหา จัดการ Catalogue สร้างข้อมูล STAC และเผยแพร่ข้อมูลเชิงพื้นที่ผ่าน Vallaris Maps

เปิด Postman Collection ต้นฉบับ
48 endpointsSTAC API / Catalogue APIอ้างอิง Postman Collection

1. ภาพรวม

Collection นี้มี API สองกลุ่มสำหรับงานคนละบทบาท โดยใช้ header API-Key กับทุก request ที่ระบุใน Collection

STAC APIสร้างและจัดการโครงสร้าง STAC, Catalog, Collection, Item และ Queryable
Catalogue APIจัดการรายการ Catalogue ที่เชื่อมกับ STAC และใช้เป็นจุดเริ่มต้นของผู้ใช้ปลายทาง
Search & Downloadค้นหารายการภาพแบบ STAC Search และดาวน์โหลด asset ของ Item
ขอบเขตของคู่มือนี้: แสดง request, URL, parameter และ payload ตาม Collection เท่านั้น ยังไม่รวมตัวอย่าง response จริงหรือ error code
Catalogue→STAC→Collection→Item / Asset→Search / Download

2. การเตรียมใช้งาน

2.1 ตั้งค่า Postman Environment

Import Collection แล้วกำหนดตัวแปรด้านล่างใน Environment หรือ Collection Variables โดยไม่ commit key ลง Git และไม่วาง key จริงในเอกสารสาธารณะ

Windows 64-bitดาวน์โหลด Postman
macOS Apple Siliconดาวน์โหลด Postman
macOS Intelดาวน์โหลด Postman

หากไม่แน่ใจเรื่องรุ่นของเครื่อง ให้เปิด หน้า Download ของ Postman เพื่อเลือกระบบปฏิบัติการที่เหมาะสม

ตัวแปรความหมายตัวอย่าง
hostBase URL ของ Vallaris APIhttps://<your-host>
apikeyAPI key ที่ส่งใน headerYOUR_API_KEY

2.2 รูปแบบ Authentication

API-Key: {{apikey}}

2.3 ตรวจสถานะบริการ

GET {{host}}/stac/health
GET {{host}}/catalogue/health
ข้อควรระวัง: API key ใน payload สำหรับสร้าง Catalogue เป็นข้อมูลอ่อนไหว ให้ใช้ placeholder ในคู่มือ และส่งค่าจริงผ่านช่องทางที่องค์กรอนุมัติเท่านั้น

3. ค้นหาและดาวน์โหลดข้อมูล

3.1 ดูรายการ Catalogue

GET {{host}}/catalogue/1.0/catalogues?limit=100
API-Key: {{apikey}}

ใช้ catalogueId จากรายการที่ได้รับเพื่อค้นหา STAC ของ Catalogue นั้นในขั้นตอนถัดไป

3.2 ค้นหา Item ด้วย POST

POST {{host}}/catalogue/1.0/catalogues/:catalogueId/stac/search
API-Key: {{apikey}}
Content-Type: application/json

{
  "collections": ["YOUR_COLLECTION_ID"],
  "bbox": [102.491455, 15.082732, 105.325928, 17.161786],
  "datetime": "2021-03-23T03:19:32.708Z/..",
  "filter": {
    "op": "and",
    "args": [
      { "op": ">=", "args": [{ "property": "sun_azimuth" }, 100] },
      { "op": "=", "args": [{ "property": "imaging_mode" }, "MS"] }
    ]
  },
  "sortby": "-id",
  "offset": 0,
  "limit": 10
}

Fields เช่น ids, collections, bbox, intersects, datetime, filter, sortby, offset และ limit ใช้ประกอบกันได้ตามเงื่อนไขค้นหา

3.3 ดาวน์โหลด Asset

GET {{host}}/catalogue/1.0/catalogues/:catalogueId/collections/:collectionId/items/:itemId/download?asset=S3:zip&redirect=false
API-Key: {{apikey}}

4. จัดการ Catalogue

Catalogue ทำหน้าที่เชื่อมรายการที่ผู้ใช้ค้นหาได้เข้ากับ stac_id ของ STAC ที่เผยแพร่แล้ว

4.1 สร้าง Catalogue

POST {{host}}/catalogue/1.0/catalogues
API-Key: {{apikey}}
Content-Type: application/json

{
  "title": "THEOS ARD",
  "stac_id": "THEOS_ARD",
  "api_key": "YOUR_CATALOGUE_API_KEY",
  "source": "internal",
  "enabled": true
}

ค่าที่สำคัญคือ title, stac_id, source และ enabled ส่วน api_key ต้องไม่แสดงเป็นค่าจริงในคู่มือหรือ source code

4.2 วงจรการจัดการ

สร้าง→ตรวจรายการ→แก้ไข→เปิด/ปิดใช้งาน→ลบเมื่อเลิกใช้งาน

5. สร้างและเผยแพร่ STAC

5.1 ลำดับงานที่แนะนำ

  1. สร้าง STAC root เพื่อเป็นพื้นที่ครอบชุดข้อมูล
  2. เพิ่ม Catalog เมื่อจำเป็นต้องแบ่งลำดับชั้น
  3. สร้าง Collection เพื่อระบุขอบเขตเชิงพื้นที่และช่วงเวลา
  4. เพิ่ม Item/Feature พร้อม geometry, properties และ assets
  5. กำหนด Queryable สำหรับฟิลด์ที่จะนำไปค้นหา
  6. สร้าง Catalogue ที่อ้างอิง stac_id เพื่อเปิดให้ผู้ใช้ค้นหา

5.2 สร้าง STAC root

POST {{host}}/stac/1.0/stacs
API-Key: {{apikey}}

{
  "id": "THEOS_ARD",
  "title": "THEOS ARD",
  "description": "THEOS ARD STAC catalogue",
  "status": "Publish",
  "require_auth": "true"
}

5.3 สร้าง Collection และ Item

POST {{host}}/stac/1.0/:stacId/collections
POST {{host}}/stac/1.0/:stacId/collections/:collectionId/items

Collection: id, type, stac_version, extent, license, summaries
Item:       id, type=Feature, geometry, properties.datetime, collection, assets

Asset ใน Item กำหนดเป็น object เช่น visual หรือ thumbnail โดยระบุ href, type, title และ roles

5.4 กำหนด Queryables

ใช้ Queryable ระดับ STAC root หรือ Collection เพื่อเผยแพร่ชื่อฟิลด์ที่ระบบค้นหาได้ แล้วนำ field นั้นไปอ้างอิงด้วย filter.property ใน STAC Search

Catalogue API — หน้าที่ของแต่ละเส้นทาง
MethodEndpointหน้าที่
POST/catalogue/1.0/cataloguesสร้างรายการ Catalogue ใหม่และผูกเข้ากับ stac_id เพื่อเปิดชุดข้อมูลให้ผู้ใช้ค้นหาได้
GET/catalogue/1.0/cataloguesดึงรายการ Catalogue สำหรับแสดงหรือให้ผู้ใช้เลือกก่อนเริ่มค้นหาข้อมูล
GET/catalogue/1.0/catalogues/:catalogueIdอ่านรายละเอียด Catalogue เฉพาะรายการจาก catalogueId เช่นข้อมูลที่ผูกกับ STAC และสถานะการใช้งาน
PUT/catalogue/1.0/catalogues/:catalogueIdแก้ไขข้อมูลตั้งค่า Catalogue เช่นชื่อ แหล่งข้อมูล แท็ก หรือสถานะเปิด/ปิดการใช้งาน
DELETE/catalogue/1.0/catalogues/:catalogueId?forever=trueลบ Catalogue ตามรหัสที่ระบุ โดย forever=true ใช้สำหรับลบถาวร
POST/catalogue/1.0/catalogues/:catalogueId/stac/searchค้นหา STAC Item ภายใน Catalogue ด้วยเงื่อนไข เช่นพื้นที่ ช่วงเวลา filter การเรียงลำดับ และการแบ่งหน้า
GET/catalogue/1.0/catalogues/:catalogueId/stac/:stacPathอ่าน STAC resource ที่อ้างอิงจาก Catalogue เช่น landing page, Collection, Item หรือ Queryable โดยส่ง path ต่อท้ายใน stacPath
GET/catalogue/1.0/catalogues/:catalogueId/collections/:collectionId/items/:itemId/download?asset=S3:zip&redirect=falseขอดาวน์โหลด asset ที่เลือกจาก Item โดยระบุชื่อ asset และกำหนดพฤติกรรมการ redirect ได้
GET/catalogue/healthตรวจสอบความพร้อมใช้งานของบริการ Catalogue API ก่อนเรียกใช้งานจริง
ก่อนนำไปใช้จริง: ตรวจสิทธิ์ API key, naming convention ของ ID, และนโยบายการลบข้อมูลกับผู้ดูแลระบบก่อนเรียก endpoint ที่เปลี่ยนแปลงหรือลบข้อมูล
